## Summary

Phase 6.2 is approved for the next gated milestone. The browser suite is a real-stack Chromium gate:
it signs in through the application, uses real REST routes and JWTs, runs against a freshly migrated
disposable PostgreSQL database, seeds its data through production routes, and forces providers to

client's response path. They do not substitute dashboard data.

### MEDIUM

**403 refresh is preserved but not labelled as an access refusal.**

- Locations: `frontend/src/pages/Dashboard.jsx:50-53`, `frontend/src/pages/Dashboard.jsx:221-224`,
  `frontend/e2e/session.spec.js:37-64`.
- Scenario: if a role's dashboard permission is revoked while its session remains valid, the API
  returns 403. The session correctly survives, but Dashboard collapses that refusal into the generic
  `Refresh failed` banner. This does not falsely sign the user out, but it fails to distinguish an
  authorization refusal from a transport failure at that point in the UI.
- Smallest safe correction: retain the response status in the dashboard refresh state and render a
  dedicated in-place refusal message for 403 while retaining the last good snapshot. Extend the E2E
  test to assert that explicit wording. Do not change the axios 401/403 session behavior.
- Missing test: explicit denied-state wording and accessible status semantics for a dashboard-refresh
  403.

This is approved as a follow-up because the underlying 401/403 security behavior is correct and
because the state remains truthful and non-destructive. Keep it out of Phase 6.3 unless separately
authorized.

### LOW

**CI wording about the disposable E2E password is imprecise.**

- Location: `.github/workflows/ci.yml:308-310`, alongside the intentional CI-only literal at line
  284.
- Scenario: the comment says the seed password is "never committed", while a non-secret,
  disposable password is intentionally defined in the workflow. The implementation is safe, but the
  wording conflicts with the repository's accuracy standard.
- Smallest safe correction: say it is a CI-only value with no account outside the disposable
  database, rather than saying it is never committed.
