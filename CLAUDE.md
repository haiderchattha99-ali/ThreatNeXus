## Working rules

- **Phase-gated. One phase, one PR, at a time.** Phase 0 first. Do not start a later phase before the
  current phase's gate (defined in `BUILD_PLAN.md`) passes.
- **Audit logging is cross-cutting and begins in Phase 0.** Every write path added later appends its
  own `AuditLog` event in the same change — never retrofit it.
- **One Shadowserver-style report type first** (Accessible RDP exposure), carried to closure before a
  second type is started.
- **Deduplication, persistence, and recurrence are core invariants.** Dedup key:
  `(indicator_value, port, protocol, report_type)`. Existing finding + open case → persistence (bump
  occurrence, no new row). Existing finding + closed case → recurrence (reopen the case, audit it).
- **AbuseIPDB is the required first real IOC enrichment provider**, behind a provider abstraction,
  with a `MockProvider` for all automated tests (never consume live quota).
  **Enrichment failure must never block ingestion** — findings are still created; the enrichment row
  records `FAILED` or `RATE_LIMITED`. API keys from environment variables only, never in logs.
- **KEV, EPSS, and NVD are vulnerability enrichment** — a separate path from IOC reputation
  enrichment. Neither substitutes for the other.
- **Risk scoring is deterministic and explainable, never AI-decided.** Every score stores its factor
  contributions; the explanation is rendered from those, not generated by a model.
- **Manual framework mapping must work before AI assistance is added.**
- **AI is optional and disabled by default** (`AI_ENABLED=false`). AI cannot approve, send, score,
  close, resolve, or make final framework mappings. Every core workflow must complete with AI off.
- **Analyst approval is required before notification export.** The export endpoint refuses any
  notification whose status is not `Approved` or whose `approved_by` is null.
- **Out of scope:** live scheduled Shadowserver API ingestion, automatic notification sending (no
  SMTP/webhook client at all), automatic remediation verification, SIEM/EDR integration,
  threat-actor attribution, automatic compliance assessment.
- **No secrets or real victim data may ever be committed.**

## Process rules

- Inspect the actual diff and run available tests before claiming a task complete.
- **Only one coding agent edits this repository at a time.** If you find unfamiliar uncommitted
  changes, stop and review before continuing.
- **Never edit `main` directly.** Work on a feature/chore branch per phase or task.
- Do not create additional planning files here — planning lives in `ThreatNeXus-Planning/`.
